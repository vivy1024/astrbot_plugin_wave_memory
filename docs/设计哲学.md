# WaveMemory 设计哲学

这份文档解释 WaveMemory 为什么长这样：每条原则背后是一次线上事故、一次评测，或者一次被证明行不通的方案。它不是愿景清单，而是已经落在代码和配置里的决定。

---

## 1. Bot 是一个人

**决定**：记忆、心情、信念、关切、关系，全部按 Bot 本人划界，且只有一份——不按群拆成多个人格。

群聊 Bot 最容易做出的错误抽象是「一群一份记忆」。那样 Bot 在 A 群被气到，到 B 群照样开心；在一个群答应的事，换个群就忘了。真人不是这样。

所以 v5 把记忆的边界从「群」改成了「Bot + 群 + 私聊」的组合作用域：

- 她只记得自己亲历的事——同一部署里另一个 Bot 见过的消息，她召回不到；
- 心情只有一份，跨群、跨私聊延续；
- 事实跟人走：在 A 群知道的事，到 B 群也知道；私聊里听到的秘密，只留在那个私聊；
- 换 QQ 号、换平台，记忆不断线——一个 Bot 可以绑定多个账号，会话前缀固定。

由此还有一个推论：**人格不是一套 prompt，而是记忆的累积**。prompt 只写性格底色；她今天是谁，由她经历过什么决定。

## 2. 记住一切，想起来再筛选

**决定**：所有消息入库，不提前判断价值；质量交给检索和分层，不交给写入门槛。

很多记忆系统在入库时就开始「瘦身」：只存最近 N 条、只存摘要、定期合并。这些做法省资源，但丢的是不可恢复的信息——一句当时看似无聊的「我下周三考科目三」，一周后正是该被想起的那句。

WaveMemory 的记忆只增不删：存储第一位，拟人建立在记忆之上。

代价是存储和检索的重担，所以我们把工夫花在后端：
- 热 / 冷两层索引（近期活跃在 HNSW，老记忆由标签映射回库）；
- 原词检索 + 语义召回双路，互相兜底；
- 噪声记忆定期物理清理，正式记忆只增不删。

「想起来」可以慢慢变好，「没记住」永远补不回来。

## 3. 没有证据不进人格

**决定**：凡是会塑造 Bot「怎么看人、怎么说话」的内容，必须带证据，且默认经过人工审核。

LLM 会一本正经地编。如果让后台任务自动从聊天记录里「提炼事实」，几周后库里就堆满「某人被称为某某」式的复读噪声，还把群友的反串当成严肃事实。（这不是假设，是 v5 之前的真实状态：27782 条自动提炼的事实全部积压待审。）

所以现在的规则是：

- **事实**必须挂群友原话和来源记忆，反串不升格为客观事实；
- **黑话**必须指出处，可以追溯到原始聊天上下文；
- **信念**（Bot 自己的看法）只能由她每天写完日记后反思形成，要有日记依据、在不同日子里被印证才算「形成」；
- 管理台的人工批准是最后一道门；自动审核只放行证据齐全、无冲突的，把需要拿主意的留给你。

这套「现场提审 + 人工审核」取代了「后台盲抽」。审核不是负担，是把「她的人格里有什么」的决定权留在人手里。

## 4. 回复当下零 LLM，模型只做事后功

**决定**：检索路径不调用聊天模型；模型的全部戏份在对话之外。

回复当下的延迟是用户体验，检索必须便宜、稳定、可预测：一次 embedding 查询 + 本地计算，几百毫秒内完成，五个阶段全部是纯算法。

大模型只在四个时机工作：

1. **事后记账**：对话停下后回看一遍，记印象、好感、事实、黑话、关切；
2. **每晚写日记**；
3. **日记后的信念反思**；
4. **后台打标签 / 提炼黑话 / 风格**。

这个分工还带来一个工程福利：每个后台任务用什么模型可以单独配置（模型分工），便宜的 flash 足够应付大部分，只有写日记值得用更好的模型。

## 5. 每一步都可观测

**决定**：不允许「她为什么这么回答」变成一个无法回答的问题。

- **注入观测台**：每次回复的完整 trace——14 个通道各自命中什么、为什么跳过、各花多少时间、多少 token；
- **反向溯源**：任何一条记忆能查到被哪些回复用过；
- **检索实验室**：同一句话对比不同检索算法的结果；
- **版本可见**：`/api/health` 显示线上实际运行的提交号；
- **入库报警**：消息静默丢（比如换号没绑定）会在健康检查降级标红——这个功能的来历就是一次 20 小时的静默丢消息事故。

「能查」优先于「看起来没问题」。

## 6. 零外部基础设施

**决定**：SQLite + Embedding，没有 Neo4j、Elasticsearch、独立向量库、外部消息队列。

这不是简陋，是刻意：一个个人能长期单机跑住的记忆系统，比架构正确但没人维护得起的系统有价值。相应地，工程上要自己解决 SQLite 不擅长的事：

- 并发写：单一写入口 + 写协调器串行化；
- 可靠性：事务发件箱，派生索引（标签、共现、向量）由事件驱动、失败可重放；
- 一致性：同一操作重复提交不会写两次（幂等键）；
- 备份：在线备份接口，复制的是一致快照。

## 7. 渐进信任：新能力默认关

**决定**：任何可能改变 Bot 行为的新能力，默认关闭；先观察，再放开。

主动开口、自动审核、开口规则、表达学习、信念反思……全是默认关。带有判断力的新机制先跑「观察模式」（shadow）：只记录「这时候我会做什么」，不真做。你在管理台看几天记录，确认时机和分寸都对了，再启用。

「选择性不回复」也是同一个哲学的反面应用：主动开口时 Bot 可以正式调用 `wave_memory_hold_peace` 让这条回复不发送——**克制是一等公民的行为，带着理由被记录**，而不是「没说话」这个无法区分是 bug 还是选择的状态。

## 8. 本地优先，数据是你的

**决定**：全部数据在这台机器上，迁移和备份只是文件操作。

记忆库、向量索引、配置覆盖、Bot 资料，都在插件数据目录里。换机器 = 拷目录；备份 = 拷文件；想看数据 = sqlite3 打开。没有云端依赖意味着没有别人能改她的记忆——包括我们。

## 试过但不采用的

设计哲学的一部分是知道什么不做：

- **重排模型（reranker）弃用**：检索已有一次远端 embedding 延迟，再加一次重排调用换的质量提升不抵延迟；
- **上游 TagMemo V9.1 共现传播核弃用为默认**：两次线上 A/B 都让检索变差。根因是数据形态不符——那套算法面向「Agent 亲笔、标签规范有序的日记」，而我们的记忆是零散的群聊消息。代码保留为可选开关（`cooccurrence_kernel=row_budget`）；
- **记忆定期合并 / 摘要化弃用**：与「记住一切」冲突；
- **多机共享记忆的云后端**：超出单机设计边界，目前没有计划。

这些决定写进 CHANGELOG 的对应章节，保留完整对比数据，随时可以重新审视。
